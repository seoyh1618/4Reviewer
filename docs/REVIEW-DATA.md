# 사용자별 리뷰·입금 데이터 조회

DBeaver에서 `reviewer` 데이터베이스 → Schemas → `reviewer`를 선택하고 **새로고침**합니다. `Tables`에는 실제 저장 테이블, `Views`에는 집계용 뷰가 표시됩니다. `public` 스키마에는 앱 테이블이 없습니다. 기본 접속 정보는 [운영 문서](DEPLOYMENT.md#db-접속)를 참고하세요.

| 위치 | 이름 | 용도 |
|---|---|---|
| Tables | `users` | 사용자 식별자, 아이디, 이메일 |
| Tables | `reviews` | 현재 상품, 구매 플랫폼·판매처, 리뷰 상태, 금액·정산일 등 |
| Tables | `review_history` | 상품 등록·수정·리뷰 상태·정산 상태·삭제의 변경 전후 값 |
| Tables | `payments` | 정정 사항이 반영된 현재 유효 입금 기록 |
| Tables | `payment_history` | 입금 추가·수정·삭제 시점, 이전/이후 금액과 입금일, 당시 상품·판매처·입금자 |
| Tables | `activities` | 기존 화면용 활동 문구. 상세 변경 이력은 위 이력 테이블 사용 |
| Views | `review_details` | 현재 상품 컬럼과 총 받을 금액, 남은 상품 원가·리뷰비 |
| Views | `user_review_summary` | 사용자별 등록 누적 수, 현재 리뷰·입금·미수 집계 |

[바로 실행할 SQL 모음](REVIEW-DATA.sql)에 전체 사용자 집계, 특정 사용자 상품 목록/이력, 월별 입금, 플랫폼·판매처 집계, 삭제 상품 조회가 있습니다. 아이디 또는 이메일 자리만 실제 값으로 바꾸세요.

## 저장과 보존 기준

- 모든 상품/입금에 `user_id`, 각 이력에 `review_id`가 있어 사용자와 상품을 연결할 수 있습니다. 회원 비밀번호나 세션 토큰은 이력에 복사하지 않습니다.
- `reviews`의 22개 일반 조회 컬럼은 기존 `data`에서 PostgreSQL이 자동 생성·저장합니다. JSON을 직접 파싱하지 않고 상품명·판매처·가격 등을 조회할 수 있고, 원본과 컬럼 값이 따로 바뀌지 않습니다. 생성 컬럼은 직접 수정하지 않습니다.
- DB 트리거가 이력을 저장하므로 앱과 DBeaver에서 원본 행을 바꿀 때 모두 기록됩니다. 변경 내용과 이력은 같은 트랜잭션이며, 실패하거나 동시 수정 충돌이 난 요청은 이력을 남기지 않습니다.
- `review_history`는 전후 상품 데이터 전체와 리뷰·정산 전후 상태, 누적 입금액, 버전, 기록 시간을 보존합니다. `database_actor`는 앱 DB 계정 또는 직접 수정한 DB 계정입니다. 상품 소유자는 `user_id`로 구분합니다.
- `payment_history`는 실제 입금 기록 행의 생성·변경·삭제 이력입니다. 원래 금액/입금일과 정정 후 값이 남습니다. 현재 앱의 금액 감소 또는 입금일 정정은 이전 입금 행을 삭제하고 수정된 누적 금액을 새 행으로 기록하므로, 이력에는 해당 삭제/생성이 모두 나타납니다.
- 상품 삭제 후에도 두 이력 테이블은 유지됩니다. 명시적인 **회원 계정 영구 삭제** 시에는 개인정보가 포함된 이력도 함께 삭제합니다. 현재 서비스에는 회원 영구 삭제 API가 없으며 관리자 작업에 해당합니다.
- 앱 및 DBeaver 계정은 이력 테이블을 조회만 할 수 있습니다. 정정은 원본 상품·입금에서 하며, 이력 행을 덮어쓰거나 삭제하지 않습니다. 기존 `users`, `reviews`, `payments`의 관리 권한은 유지합니다.
- 도입 전 상품/입금이 있으면 `baseline`으로 그 시점의 상태를 한 번 기록합니다. 당시 알려진 최초 등록일은 `review_created_at`에 보존합니다. 이미 지워졌거나 덮어쓴 과거 값을 복구한 것은 아닙니다. 기존 활동 문구는 `activities`에 그대로 남습니다.

## 값과 집계 의미

- 금액은 원(KRW) 단위 정수입니다. 구매·리뷰·입금 날짜는 `YYYY-MM-DD`이며 미입력은 빈 문자열입니다. `recorded_at`은 실제 DB 기록 시각으로 시간대를 포함하고, SQL 모음은 한국 시간으로 표시합니다.
- `review_mode`: 실배송 / 빈박스. `review_format`: 사진 리뷰 / 텍스트 리뷰 / 별점 리뷰 등. `platform_name`: 기타 플랫폼은 직접 입력한 이름을 표시합니다.
- `review_status`: `todo` 작성 전, `done` 리뷰 완료.
- `settlement_status`: `pending` 입금 대기, `partial` 부분 입금, `done` 입금 완료, `none` 받을 현금 없음. 리뷰 완료와 입금 완료는 별개입니다.
- 빈박스의 상품 페이백은 구매금액, 실배송은 0원이며 리뷰비는 별도입니다. 부분 입금은 상품 페이백부터 차감하고 남는 입금을 리뷰비에 반영합니다.
- `registered_count`는 삭제 상품을 포함한 등록 상품 누적 수입니다. 도입 전 현재 남아 있던 상품도 포함하며, 도입 전에 삭제된 상품을 추정해 더하지 않습니다.
- `active_review_count`, `review_done_count`, `settled_count`와 금액 집계는 **현재 남아 있는 상품** 기준입니다. `deleted_count`, `ever_review_done_count`, `ever_settled_count`는 삭제/정정 이후에도 보존된 이력에서 확인한 누적 상품 수입니다.
- 이력의 금액을 단순 합산하면 정정/삭제가 중복될 수 있습니다. 현재 입금액은 `payments` 또는 `user_review_summary.received_total`, 현재 미수금은 `review_details`를 사용하세요. 삭제 상품의 마지막 상태는 SQL 7번으로 별도 조회합니다.
- 입금 이력의 음수 `amount_delta`는 기록 정정/삭제를 뜻하며 실제 출금 또는 환불 증빙이 아닙니다.

PostgreSQL [생성 컬럼](https://www.postgresql.org/docs/17/ddl-generated-columns.html)과 [트리거](https://www.postgresql.org/docs/17/sql-createtrigger.html)를 사용합니다. 운영 데이터에 대한 쓰기 권한을 추가로 공개하거나 외부 DB 포트를 확장하지 않습니다.

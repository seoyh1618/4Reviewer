# For Reviewer 제품·개발 계획

## 목적과 디자인

리뷰 참여자가 수기로 작성하는 스프레드시트를 개인별 워크스페이스로 전환한다. 구매 → 리뷰 마감 → 리뷰 완료 → 입금 확인을 연결해 누락과 반복 입력을 줄인다. 참고 스크린샷의 실제 이름·연락처·상품 기록은 예시 데이터로 가져오지 않는다.

로그인과 기본 워크스페이스 구성은 사용자가 지정한 [SocialMemAgent](https://github.com/seoyh1618/SocialMemAgent)를 참고한다. 확인한 커밋은 `089b77dece9ec873b1c2ce8306d6df0f0de6effb`. 중앙 흰색 로그인 카드, SIGN IN/SIGN UP 제목, 지문 아이콘 및 원형 궤도, 파란색 로그인 버튼의 배치를 재구현했다. 서비스명은 For Reviewer로, 궤도 아이콘은 상품·리뷰·페이백으로 바꾼다. 메인은 최신 요청에 따라 흰색 사이드바와 밝은 작업 배경(#f8fafc), 둥근 흰색 카드와 기존 글자 굵기를 사용한다. 사이드바의 등록 상품·완료한 리뷰·주문내역 등록 카드는 회색 바탕 대신 흰색 바탕, 옅은 테두리, 둥근 모서리와 은은한 그림자로 구분한다. 등록 상품·완료한 리뷰는 흰색 카드에 검정 계열 숫자로 통일한다. 색상만 조정하여 메뉴 글자는 #334155, 선택 메뉴는 차분한 파란 배경(#dce7f6)과 진한 파란 글자(#1e40af), 사이드바 구분선은 #d8e0eb로 표시한다. 접힌 아이콘 메뉴에도 같은 선택 색을 적용한다. 받을 페이백의 금액과 입금 대기 문구는 검정 계열을 유지한다. 초기 SLDS 2 요청의 깔끔한 입력·상태 컴포넌트 원칙을 유지한다. Salesforce 제품 또는 LWC 자체가 아닌 독립 React 웹앱이다. PC는 테이블, 모바일은 카드·하단 내비게이션·전체 높이 등록 폼을 사용한다.

## 1차 개발 범위

1. 이름 입력 없는 이메일 회원가입·로그인·로그아웃, 계정별 데이터 격리, 서버 저장.
2. 상품 CRUD: 상품명, SKU, 주문번호, 구매 계정명, 판매처, 구매 플랫폼(쿠팡·네이버·11번가·기타 직접 입력), 리뷰 타입(실배송·빈박스), 구매일, 구매금액, 리뷰 유형, 리뷰 마감일, 리뷰 상태, 실제 리뷰 작성일, 예상 페이백, 추가 리뷰비, 실제 입금액, 정산일, 입금자명, 연락처, 카톡 이름, 메모.
3. 리뷰 대시보드: 받을 페이백과 작성해야 할 리뷰를 첫 두 지표로 배치하고 0원·0건도 표시한다. 받은 페이백, 누적 구매, 가까운 마감과 최근 상품을 함께 제공한다. 최신 요청에 따라 대시보드·내 리뷰·페이백·캘린더·통계·템플릿의 제목 아래에 짧은 안내 부제목을 표시한다.
4. 검색·플랫폼·리뷰 타입/진행상태 필터·정렬·CSV 내보내기·월간 리뷰 캘린더·월별 통계. 상품명 고정 및 가로 스크롤 표에서 18개 열 개별 선택과 전체 선택·핵심 열 전환. 계정주·연락처·카톡 이름·입금자명도 검색.
5. 신규 등록은 구매금액 옆에 리뷰비를 입력하며 예상 페이백을 직접 입력하지 않는다. 빈박스는 상품 가격과 리뷰비, 실배송은 리뷰비만 포함한 총 받을 금액을 안내한다. 구매금액·리뷰 타입 수정·OCR 적용 시 같은 규칙으로 갱신하고 입력한 리뷰비는 유지한다. 기존 기록 수정에서도 상품값 페이백은 리뷰 타입으로 자동 계산한 읽기 전용 값이다. 신규 등록은 작성 전·누적 입금액 0원으로 시작하며 실제 입금액·정산일·입금자명·리뷰 상태·리뷰 작성일 입력은 제외한다. 목록·모바일 카드·상세의 작성 전 → 리뷰 완료 → 정산 완료 단계에서 실제 작성일·유형·메모, 입금액·입금일·입금자명을 저장한다. 마감일 미정 시 비워도 된다고 안내하고, 카톡 이름에는 실제 오퍼를 보낸 상대방의 이름을 입력하도록 도움말을 제공한다.
6. 주문내역 이미지 OCR: 한국어 중심 기기 내 인식, 작은 캡처 확대, 진행률, 자동 폼 입력, 결과 원문 수정·재적용 후 사람이 검토. 쿠팡 단일 상품 카드와 같은 줄의 구매일·주문번호를 읽고 최종 결제금액을 우선한다. 인식되지 않은 정보는 추정하지 않는다. 이미지 원본은 서버에 전송·보관하지 않는다.
7. 모든 신규 계정은 빈 상품 목록으로 시작한다. 예시 데이터 체험 진입은 제공하지 않는다.
8. 리뷰 템플릿: 간단한 후기·사진·식품·뷰티·생활용품·한 달 후기 6종을 제공한다. 이름·유형·내용 수정과 개인 템플릿 생성, 본문 복사, 이름/내용 검색 및 유형 필터를 지원한다. 사용자가 직접 그룹을 만들고 템플릿 생성·수정 시 소속 그룹을 선택할 수 있다. 그룹별 개수와 필터, 그룹 이동 및 미분류 복귀를 지원하며 기존 템플릿은 미분류로 유지한다. 그룹과 소속 정보는 계정별로 저장한다. 모바일 하단 메뉴에는 ‘템플릿’으로 표시한다.
9. 추가 리뷰비는 상품값 페이백 외에 추가로 받는 금액이다. 신규 등록의 구매금액 옆에서 선택적으로 입력하며 기본값은 0원이다. 구매금액 변경·OCR 적용 시에도 입력한 리뷰비를 유지하고, 리뷰 완료·정산 단계 또는 기록 수정에서 변경할 수 있다. 상세·진행 단계에서 예상 페이백과 추가 리뷰비를 구분해 보여주고 총 받을 금액을 즉시 계산한다. 정산창의 입금액 기본값은 미정산 잔액이며, 사용자가 직접 바꾼 실제 입금액은 리뷰비를 수정해도 유지한다.

## 핵심 집계 규칙

- 총 구매금액 = 상품 구매금액 합계. 추가비용은 입력·집계·CSV에서 제외한다. 페이백은 수익으로 표시하지 않는다.
- 총 받을 금액 = 예상 페이백 + 추가 리뷰비. 기존 추가비용은 리뷰비로 전환하지 않고, 추가 리뷰비가 없는 기존 기록은 0원으로 읽는다.
- 상품값 페이백은 빈박스일 때 구매금액, 실배송일 때 0원이다. 실배송은 리뷰비만 정산하고 리뷰비가 0원이면 총 받을 금액도 0원이다. 리뷰 타입이 지정되어 있으면 과거 자동/직접 입력 설정보다 배송 기준을 우선한다. 리뷰 타입이 없는 구형 기록은 기존 페이백을 그대로 읽으며 수정 시 리뷰 타입을 선택한다. 조회 시 저장 원본이나 실제 입금 이력은 변경하지 않는다.
- 받을 금액 = 각 상품 max(총 받을 금액 - 실제 입금액, 0)의 합계.
- 받은 금액 = 실제 입금액 합계. 추가 리뷰비도 실제 입금된 후 반영한다. 구매월과 입금월은 따로 집계한다.
- 완료 리뷰 = 리뷰 상태 완료. 입금 상태와 독립적이다.
- 리뷰 캘린더 = 리뷰 완료 상태이면서 실제 리뷰 처리일(reviewedAt, 입력창의 리뷰 작성일)이 있는 기록. 월별 건수·날짜 셀·선택일 목록은 모두 처리일 기준이며 마감일·구매일로 대체하지 않는다. 완료·날짜 수정·작성 전 복귀를 즉시 반영한다. 마감 알림과 대시보드의 마감 확인은 내 리뷰의 마감 임박 목록으로 연결한다.
- 정산 완료 = 실제 입금액이 0원보다 크고 총 받을 금액 이상인 상품. 부분 입금과 실제 입금 없이 총 받을 금액이 0원인 정산 없음은 제외한다. 기존 입금 기록은 배송 기준으로 재계산해도 보존한다. 상품값 페이백이 0원이어도 추가 리뷰비가 있으면 정산할 수 있다.
- 내 리뷰은 전체 상품·작성 전·리뷰 완료·마감 임박·정산 완료로 필터링한다. 리뷰 작성 상태와 정산 상태는 독립적이므로, 리뷰 작성과 입금이 모두 끝난 상품은 리뷰 완료와 정산 완료 양쪽에서 조회된다. 마감 임박은 작성 전이면서 마감일까지 3일 이내인 상품(기한 경과 포함)이다.
- 날짜·마감은 한국 시간 기준 날짜 문자열, 화폐는 원 단위 정수, 빈 날짜는 미정이다.
- 일반 진행 흐름에서는 리뷰 완료를 저장한 후 정산 입력을 연다. 부분 입금은 정산 대기로 남고, 전액 입금이면 정산 완료다. 총 받을 금액 0원은 정산 없음으로 표시한다. 기존 기록 수정에서는 리뷰와 입금 상태를 독립적으로 보존한다. 추가 리뷰비는 저장할 때 누적하지 않고 입력한 값으로 대체하며, 이미 받은 금액보다 총 받을 금액을 낮출 수 없다.
- 목록·상세의 진행 단계 막대는 화살표 없는 다음 단계 버튼 하나로 대체한다. 내 리뷰·페이백 표는 화면의 가용 너비를 사용하고 셀 여백 6px × 10px, 약 47px 행 높이, 페이지당 20개로 구성한다. 단계 버튼은 상품명 셀에서 분리해 맨 오른쪽에 고정한 ‘진행 단계’ 컬럼에 표시하며, 표시할 열에서 켜고 끌 수 있다. 작성 전은 ‘리뷰 완료’, 리뷰 완료 후 미정산·부분 입금은 ‘정산 완료 전환’을 표시하고 클릭 시 해당 입력 모달을 연다. 리뷰와 입금이 모두 완료되면 버튼 대신 완료 문구만 표시한다. 선입금 상품도 리뷰가 작성 전이면 리뷰 완료 버튼을 유지한다. 받을 금액이 0원인 상품은 정산창에서 추가 리뷰비를 입력할 수 있으며, 0원 입금 저장은 허용하지 않는다. 기존 리뷰의 작성일·유형·리뷰비·메모 수정은 상세의 ‘리뷰 정보 수정’으로 제공한다. 상태 배지와 정산 계산 기준은 그대로 유지한다.
- 단계 저장 응답의 리뷰와 실제 입금 원장을 즉시 반영하여 대시보드 합계와 입금월별 통계를 함께 갱신한다. 입력창 취소는 값을 저장하지 않으며, 오류·버전 충돌 때는 창과 입력을 유지한다. 저장 중 재클릭을 막고 최초 입력 시점의 버전으로 중복·동시 수정 충돌을 검증한다.

## 구조와 상호작용 계약

- 내 리뷰의 내보내기 오른쪽에 ‘칸반뷰로 보기’를 배치하며 전환 후 ‘테이블뷰로 보기’로 복귀할 수 있다. 검색·플랫폼·리뷰 타입·상태·정렬·내보내기는 공통이고, 표시할 열과 페이지 이동은 테이블에만 적용한다. 칸반은 필터된 전체 결과를 작성 전·리뷰 완료·정산 완료에 중복 없이 배치한다. 작성 상태가 우선하므로 선입금된 작성 전 리뷰는 작성 전, 부분 입금이나 정산 없음인 완료 리뷰는 리뷰 완료, 작성과 실제 입금이 모두 완료된 리뷰는 정산 완료에 속한다. 마감 임박은 카드에 표시한다. 상단 KPI·상태 탭은 기존의 독립적인 리뷰/입금 집계를 유지한다.
- 칸반은 회색 열 제목·건수, 흰색 카드, 얇은 테두리를 사용한다. 카드에 상품명·판매처·플랫폼·리뷰 타입·가이드·단계별 날짜·구매가와 다음 단계 버튼을 표시한다. 카드 본문은 상세 모달을 열고, 단계 버튼은 기존 입력 모달을 열어 저장 성공 후에만 이동한다. 부분 입금은 리뷰 완료 열에 남는다. PC는 3열, 모바일은 가로 스크롤과 44px 단계 버튼, 각 열은 세로 스크롤을 제공한다. 보기 방식은 현재 계정·브라우저별로 저장되며 새로고침과 메뉴 복귀에도 유지한다.

- 사이드바는 상단 왼쪽 햄버거 버튼으로 접고 펼친다. 821px 이상에서 접으면 76px 너비의 아이콘 메뉴가 되고 본문이 넓어진다. 선택 메뉴 강조, 메뉴 이름 툴팁, 주문내역 가져오기·도움말·계정·로그아웃을 유지한다. 상태는 현재 브라우저에 저장하며 저장소를 사용할 수 없어도 토글은 동작한다. 820px 이하에서는 기존 하단 메뉴를 유지하고 PC로 돌아오면 접기 상태를 복원한다. 키보드 Enter/Space 및 스크린 리더용 펼침 상태를 제공한다.

- 월별 차트 금액 확인: 구매·입금 비교를 기존 React DOM 막대차트에서 제공한다. 대시보드와 통계가 같은 컴포넌트를 사용하며 화면당 1개다. 기본 최근 6개월, 통계의 연도 선택 시 12개월, 월 선택 시 해당 1개월을 표시한다. 집계와 막대 높이 인코딩은 유지하고 React가 월 선택·호버·키보드 초점과 금액 팝업을 소유한다. 새 차트 라이브러리나 별도 렌더러는 추가하지 않는다.
- 통계 기간 필터: 전체 데이터 내보내기 왼쪽에 연도와 월 선택란을 배치한다. 기본 전체 기간에서 연도를 선택하면 전체 월, 월을 추가로 선택하면 해당 월을 집계한다. 연도 목록은 구매일·실제 입금일의 연도와 현재 연도를 포함한다. 구매·리뷰·미정산 현황은 기간 내 구매 상품의 현재 상태, 실제 입금액은 해당 기간의 입금 원장으로 집계하므로 이전 기간 구매의 입금도 포함된다. 통계 카드·플랫폼 요약·차트·상세 표를 같은 기간으로 갱신한다. 전체 기간의 차트·표는 기존 최근 6개월이며, 전체 데이터 내보내기는 전체 상품 기록을 유지한다.
- 기간은 URL의 statsYear·statsMonth로 유지하고 새로고침·뒤로/앞으로 가기에서 복원한다. 잘못된 연도는 전체 기간, 잘못된 월은 전체 월로 정규화하며 연도 없이 월만 선택하지 않는다. 연도·월 변경 시 차트의 임시 선택은 해제한다. 모바일에서는 기간 두 선택란을 한 행, 내보내기를 다음 행으로 배치한다. 연간 차트는 월별 44px 이상 터치 영역과 내부 가로 스크롤을 제공하고 금액 팝업은 보이는 차트 영역 안에 둔다. 표는 차트의 대체 표현이며 기록이 없는 월은 0으로 표시한다.
- 금액 팝업에는 연월·구매금액·실제 입금액을 원 단위로 표시한다. 마우스 호버와 키보드 초점은 임시 표시, 클릭·터치는 선택 유지, 다시 선택·바깥 누르기·Escape는 해제한다. 선택은 화면 안의 일시적 상태로 URL이나 저장소에 기록하지 않는다. 기본 막대와 직접 표시된 값, 통계의 월별 표는 그대로 제공한다.
- 작은 화면에서도 월 전체 영역을 터치 대상으로 사용하고 기본 스크롤을 막지 않는다. 팝업은 차트 폭 안에 배치하며 데스크톱·모바일 세로/가로 화면, 첫 달·마지막 달·0원·큰 금액·입금월이 다른 기록·상태 갱신·키보드·접근성을 확인한다. 집계 자료가 갱신되면 열린 팝업도 같은 자료를 읽는다. 추가 네트워크 요청이나 지속 애니메이션은 없다.
- React + TypeScript + Vite 클라이언트, Express API, Node 24 SQLite 영속 저장. 단일 서버 MVP이며 다중 인스턴스 확장 시 PostgreSQL 전환.
- React가 필터·표·DOM 막대 차트·달력을 소유한다. 차트는 최대 12개월·24개 막대이며 차트와 표가 집계 결과를 공유한다. 플랫폼 요약은 직접 입력한 플랫폼까지 이름별로 묶는다. Canvas/WebGL 불필요. 대체 표현은 직접 표시되는 금액과 요약 표다.
- 메뉴·필터·검색은 URL 쿼리로 유지. 상품·세션은 서버에 유지. 테이블은 페이지당 8~12개, 통계는 개인 데이터의 선택 기간 기준.
- 상품·페이백 목록 도구는 왼쪽 검색창, 오른쪽 모든 플랫폼 → 최근 구매순 → 표시할 열 순서로 한 행에 배치한다. 600px 이하에서는 검색창과 세 가지 도구를 두 행으로 배치한다. 고정 열·가로 이동 안내 문구는 표시하지 않는다.
- 표시할 열은 접을 수 있는 흰색 패널에서 상품 정보·리뷰 정보·정산 정보·연락처별 버튼으로 선택한다. 선택한 항목은 연한 회색 배경과 진한 회색 글자·체크 아이콘, 선택하지 않은 항목은 흰색이다. 검색·필터 행과 패널 사이에는 PC 20px·모바일 16px 여백을 둔다. 상품명은 항상 표시한다. 열 선택은 PC 표에 적용하며, 계정과 상품/페이백 화면별로 현재 브라우저에 저장한다. 다른 기기와 동기화하지 않는다.
- 모바일 카드는 상품명(최대 두 줄)·플랫폼·리뷰/정산 상태·마감 또는 유형·구매가(페이백 화면에서는 남은 금액)만 표시한다. 연락처·입금 상세·진행 단계는 카드 전체를 눌러 여는 상세 모달에서 제공한다. 상세는 화면 가장자리에 여백을 둔 모달이며 본문만 스크롤한다. 닫기·바깥 영역·Escape로 닫으면 목록 필터와 스크롤 위치가 유지된다. 등록·편집·단계 입력 폼은 기존 전체 화면 형식을 유지한다.
- 전체 상품·작성 전·리뷰 완료·마감 임박·정산 완료 및 페이백 탭에 각각 0건을 포함한 건수 배지를 표시한다. 상태 선택과 무관하게 현재 검색어와 플랫폼에 해당하는 전체 자료를 기준으로 세며, 목록 필터와 같은 조건을 사용한다. 모바일에서는 다섯 탭과 배지를 한 화면에 표시한다.
- 자동 스트리밍 없음. 최초 진입, 탭 재활성화, 변경 성공 및 수동 새로고침 시 조회. 마지막 동기화 시각 표시. 조회 실패 시 기존 값을 유지하고 오류·재시도 안내. 저장 실패를 성공으로 표시하지 않는다.
- 모바일 360/390/768px 및 데스크톱 1440px 검증. 기본 터치 영역 44px, 키보드 초점·모달 Escape·초점 복귀, reduced-motion 대응. OCR 클라이언트는 페이지에 포함해 재빌드 후 오래 열린 화면의 모듈 로딩 실패를 방지하고, 실제 worker·모델은 업로드 시에만 로드한다.
- 해시 비밀번호, HttpOnly/SameSite 세션 쿠키, 서버 소유권 검증, 동일 출처 쓰기 요청, 속도 제한, 입력 검증, CSV 수식 삽입 방지.
- 기본 리뷰 템플릿은 읽기 전용 원본이며, 수정한 문구와 직접 만든 템플릿은 계정별 SQLite에 별도로 저장한다. 다른 계정의 기본 문구나 기존 리뷰 집계에 영향을 주지 않는다. 템플릿 버전으로 동시 수정 충돌을 검증하며, 복사 권한이 없는 브라우저에서는 본문 선택 창을 제공한다.

## 내 리뷰 핵심 지표

내 리뷰의 테이블·칸반 위에 흰색 카드 4개를 제공한다. 첫 카드는 등록 건수와 정산 완료 수, 두 번째는 작성 전과 실배송·빈박스별 건수(구형 타입 미지정이 있으면 별도 표시), 세 번째는 리뷰 완료 수, 네 번째는 받을 페이백 총액과 상품 원가·리뷰비별 남은 금액이다. 정산 완료 수는 실제 입금 완료 여부로 계산하며 리뷰 완료 수와 독립적이다. 부분 입금과 정산 없음은 정산 완료 수에서 제외한다.

사용자가 선택한 상품 원가 우선 차감 기준을 적용한다. 각 리뷰의 남은 원가는 max(상품값 페이백 - 받은 금액, 0), 남은 리뷰비는 max(리뷰비 - max(받은 금액 - 상품값 페이백, 0), 0)이며 두 잔액의 합은 기존 받을 페이백과 같다. 실배송은 상품값 페이백 0원이다. 실제 입금 원장과 기록을 변경하지 않는 집계 규칙이며 부분 입금 건이 있으면 화면에 기준을 표시한다.

React가 한 세트의 HTML 정의 목록을 렌더링하며 차트 라이브러리·별도 요청·애니메이션은 없다. 기존 `totals`와 `reviewOverview`로 검색·플랫폼·리뷰 타입에 해당하는 전체 항목을 집계하고 상태 탭·페이지 이동에는 수치를 유지한다. 필터가 있으면 첫 카드에 검색·필터 적용을 표시한다. 조회·저장 성공 시 값이 갱신되고 조회 실패 시 기존 자료와 앱의 오류 안내를 따른다. 새 URL·저장 상태는 없다. PC는 4열로 값·단위·세부 금액을 호버 없이 제공한다. 모바일 화면(820px 이하)에서는 내 리뷰 KPI 영역과 해당 접근성 설명을 함께 숨기며 테이블·칸반 모두 동일하다. 0건·0원을 생략하지 않고 스크린리더에 집계 범위를 설명한다. 검증은 빈 결과·필터·테이블/칸반, 실배송·빈박스·미지정, 부분/전체 입금, 선입금·정산 없음, 저장 후 갱신, 모바일 배치·접근성을 포함한다.

정산일은 표·상세·수정창·CSV에서 ‘정산일’만 표시한다. ‘최근 입금일’ 보조 라벨은 삭제하고 저장된 날짜와 입금 이력은 유지한다.

## 상품 상세 구성

상품 상세의 최신 구성은 [Salesforce SLDS 모달 구성](https://developer.salesforce.com/docs/platform/lightning-component-reference/guide/lightning-quick-action-panel)을 참고한다. 흰색 바탕·옅은 회색 테두리·회색 상태 배지와 절제된 강조색을 사용하며, 정보는 PC·모바일 모두 한 행에 두 항목씩 라벨 위/값 아래로 표시한다. 변경 이력과 페이백 수령현황은 상세에서 제외한다. 헤더와 푸터를 고정하고 본문만 스크롤하며, 푸터 왼쪽에는 닫기, 오른쪽에는 수정과 정산 완료를 둔다. 작성 전의 마지막 동작은 리뷰 완료이며, 실제 정산이 끝난 항목은 완료 상태로 표시한다. 입금 내역은 유지하고 삭제 기능은 본문 하단에서 확인 후 실행한다.

## 수용 기준

서로 다른 두 계정에서 타인 상품이 조회·수정·삭제되지 않아야 한다. 새로고침/재로그인 후 기록이 유지된다. 상품 등록 → 수정 → 리뷰 완료 → 부분 입금 → 정산 완료 → CSV까지 동작한다. 샘플 주문 이미지의 OCR 결과가 실제 폼에 적용되고 수동 수정할 수 있다. 모바일에서 주요 기능을 사용할 수 있고 화면 밖 가로 넘침이 없어야 한다.

이전 기록의 리뷰 작성일·카톡 이름은 빈 값으로 읽고, 추정하거나 일괄 변경하지 않는다. 리뷰 완료로 변경할 때 오늘 날짜를 제안하며 수정할 수 있다. 작성 전으로 되돌리면 작성일을 비운다. 정산 상태는 독립적인 수동 선택 대신 실제 금액에서 계산해 금액과 상태가 어긋나지 않게 한다. 신규 등록 시 입금 원장은 만들지 않으며, 이후 정산 단계에서 실제 입금을 기록한다. 새 필드는 CSV와 모바일 상세에도 제공한다.

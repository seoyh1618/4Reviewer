# For Reviewer 검증 기록

검증일: 2026-10-28 (한국 시간). 로컬 프로덕션 빌드와 Google Chrome 자동화로 확인했다.

## 모바일 등록폼·열 정렬 (2026-10-29)

- 등록/수정 모달을 제목·본문·하단 버튼으로 나누고 본문만 스크롤한다. 모바일 입력란은 한 열, 구매금액·리뷰비는 두 열로 유지한다. 긴 문자열, 날짜 입력, 최대 금액, 기타 플랫폼, OCR 오류와 추가 관리 필드를 포함해 가로 넘침을 검사했다.
- 모바일 목록의 플랫폼·리뷰 타입·구매순·표시할 열 드롭다운을 숨기고, 열 이름을 누르면 오름차순/내림차순으로 전환한다. 기존 카드와 상세 모달을 유지한다. 데스크톱 표 머리글도 정렬할 수 있다.
- 전체 목록을 정렬한 다음 페이지를 나눈다. 검색·상태 필터·칸반·페이백·CSV·새로고침에서 정렬이 유지되며, 날짜 미입력 값은 양방향 모두 마지막에 표시한다. 데스크톱/URL에서 넘어온 필터는 모바일에서 확인·해제할 수 있다.
- 단위/API 검사 29개 통과(별도 PostgreSQL 연결이 필요한 3개는 로컬에서 제외). 등록·정산·OCR·열 선택·필터를 포함한 Chrome 21개 흐름 통과. 새 모바일 흐름의 화면 폭은 320/360/390/430px, 짧은 화면 390×400, 가로 화면 844×390이다.
- WebKit 모바일 정렬 검사는 통과했다. macOS의 WebKit 자동화 브라우저가 등록폼 검사 중 네이티브 입력 처리에서 종료되어, 최종 WebKit 등록폼 검사는 Linux CI의 필수 배포 단계에 포함했다. 실제 iPhone/Android 키보드와 사진 선택은 별도 확인이 필요하다.

## 입력 항목 변경 검증 (2026-10-28)

- 도메인·API 테스트 6개, Chrome 브라우저 흐름 4개 통과. TypeScript/Vite 빌드 성공.

- 구매 플랫폼 선택은 쿠팡·네이버·11번가·기타, 배송 방식 선택은 실배송·빈박스만 제공.

- 모바일 390px에서 기타 플랫폼·빈박스 등록, 360/390/768px 화면 가로 넘침 검사 통과.
- 추가비용 입력·안내·CSV 제거, 구매 합계에서 이전 추가비용 제외, 기존 플랫폼명 보존 확인.
- 기존 OCR 인식과 리뷰 완료·부분 입금·전체 입금 흐름도 통과.

## 대시보드 문구·파란 사이드바 (2026-10-28)

- 제목을 ‘리뷰 대시보드’로 변경하고, 각 화면의 제목 주변 인사말·홍보성 부제목·영문 장식 제목을 제거했다.
- 받을 페이백과 작성해야 할 리뷰를 첫 두 지표로 배치했다. 빈 계정에서 PC·390px 모두 0원·0건 확인, 샘플 데이터에서는 131,500원·6건 확인.
- 사이드바 배경 #3b82f6, 선택 메뉴 흰색, 대비를 확보한 남색 글자. 실제 계산 스타일 색상 확인.
- 5개 브라우저 흐름 중 4개 초기 통과. 빈 대시보드 안내 글자의 대비 문제를 수정한 후 관련 3개 흐름 재실행 통과. 대시보드·등록·상품 표 axe 검사에서 위반 없음.
- TypeScript/Vite 빌드 성공, 로컬 서버가 제공하는 최신 화면으로 열린 탭 새로고침.

## 리뷰 작성·정산 구분 (2026-10-28)

- 내 상품에서 전체 상품·작성 전·리뷰 완료·마감 임박·정산 완료 탭 제공.
- 7개 조합(작성 전/완료, 미입금/부분 입금/전액 입금/정산 없음)을 별도 테스트 계정에 저장하여 1440px·360px·390px에서 필터 결과 확인. 리뷰 완료·미입금 및 부분 입금은 정산 완료에서 제외, 작성 전·전액 입금은 정산 완료에 포함된다.
- 리뷰 완료 상품은 마감일이 가까워도 마감 임박에서 제외된다. 새로고침 후 선택한 정산 완료 필터와 결과 유지 확인.
- 모바일 탭 간격을 줄여 360px에서도 전체 구분을 확인할 수 있게 조정. 상품 수 7개 기준 탭 내부 및 페이지 가로 넘침 없음 확인.
- TypeScript/Vite 빌드 성공. 상태 필터·모바일 메뉴 흐름 최종 2개 통과. 간격 수정 전 등록→리뷰 완료→부분/전체 입금 흐름도 통과.
- 테스트는 별도 데이터베이스에서 수행했으며, 기존 사용자의 상품 기록은 수정하지 않았다.

## 표시할 열 선택·목록 도구 정렬 (2026-10-28)

- 고정 상품명·가로 이동 안내 문구와 기존 별도 열 선택 행을 제거했다. 1440px·1024px·768px에서 검색창 → 모든 플랫폼 → 최근 구매순 → 표시할 열이 같은 행이며, 선택 도구가 우측 끝에 있음을 좌표로 확인했다.
- 첨부한 컴포넌트처럼 흰색 테두리 패널, 분류 버튼, 연한 회색 하위 영역, 진한 남색 선택 버튼으로 구성했다. 개별 선택·해제, 전체 선택, 핵심 열만 선택, 접기 및 Escape 초점 복귀 검증.
- 상품명을 제외한 모든 열을 숨겨도 상품을 열 수 있다. 열 선택이 새로고침·메뉴 이동 후 유지되고 내 상품과 페이백의 선택이 분리됨을 확인했다. 저장 범위는 계정별 현재 브라우저다.
- 360px·390px에서는 검색창 아래에 세 도구를 같은 행으로 표시한다. 선택한 필드가 모바일 카드에도 반영되고 페이지 가로 넘침이 없음을 확인했다. 작은 화면의 드롭다운 이름 잘림을 수정했다.
- 상태 구분·모바일 메뉴·등록/수정/CSV 기존 3개 흐름 통과. 새 열 선택 흐름은 메뉴의 상품 수가 포함된 접근성 이름에 맞게 테스트를 수정한 뒤 통과했다. 모바일 색상 전환 중 글자 대비를 수정하고 최종 열 선택 흐름 재검증 통과. PC·모바일 axe WCAG 2 A/AA 검사 위반 없음.
- TypeScript/Vite 빌드 성공. 별도 테스트 데이터베이스를 사용했으며 기존 사용자 상품 기록은 수정하지 않았다.

## 단계별 리뷰·정산 입력 및 톤 정리 (2026-10-28)

- 메뉴·페이지 제목·목록 이름을 ‘내 리뷰’로 통일했다. 사이드바는 #f1f4f8, 선택 메뉴는 #e2ebfa, 글자와 포인트는 남색·파랑으로 맞췄다. 기존 파란 사이드바 요청은 이번 톤 정리 요청으로 대체했다.
- 표의 고정 상품명 셀·모바일 카드·상세 화면에서 작성 전 → 리뷰 완료 → 정산 완료 버튼을 제공한다. 리뷰 작성일·유형·메모 및 실제 입금액·입금일·입금자명을 각 모달에서 저장한다.
- 일반 진행에서는 리뷰 완료 후 정산 입력이 활성화된다. 부분 입금은 다음 입금을 계속 기록할 수 있고 전액 입금 후 버튼이 비활성화된다. 정산 없음과 과거 작성 전·전액 입금 자료의 독립 상태는 유지한다.
- 빈 계정에서 실제 폼으로 상품 등록 후 리뷰 완료·부분 입금·전액 입금을 진행했다. 대시보드의 작성할 리뷰 1→0건, 받을 페이백 30,000→20,000→0원, 실제 입금액 0→10,000→30,000원 및 월별 통계와 새로고침 후 저장을 확인했다.
- 작성 전/마감 임박 필터에서 완료 저장 시 리뷰 완료로, 리뷰 완료/입금 대기/부분 입금 필터에서 전액 입금 시 정산 완료로 이동한다. 정산 응답에서 실제 입금 원장을 함께 받아 통계를 즉시 갱신한다.
- 취소 시 상태 불변, 서버 저장 실패 후 입력 유지·재시도, 다른 화면에서 수정한 버전의 충돌 차단, 과입금 차단, 연속 클릭 시 중복 입금 없음(10,000원·20,000원 원장 2건) 확인.
- 390px에서 단계 입력·오류 복구·정산 저장 확인. 모달의 실제 화면 위치 0px 및 높이 844px 확인. PC·모바일 입력창과 기존 표·대시보드·열 선택의 axe WCAG 2 A/AA 검사 위반 없음. 360/390/768px 기존 메뉴·필터·캘린더·등록 검증도 통과했다.
- TypeScript/Vite 빌드 및 도메인·API 6개 통과. 영향받는 브라우저 흐름 8종을 확인했고, 마지막 필터 자동 이동 수정 후 단계 진행·모바일 오류 복구 2종을 재실행해 통과했다. OCR은 이번 변경과 무관하여 재실행하지 않았다.
- 별도 테스트 DB 사용. 실제 데이터는 수정하지 않고 로컬 서버를 새 버전으로 재시작했다.

## 리뷰 템플릿 (2026-10-28)

- PC 메뉴에 ‘리뷰 템플릿’, 모바일 하단에 ‘템플릿’을 추가했다. 기본 후기·사진·식품·뷰티·생활용품·한 달 사용 후기 6종을 제공한다. 문구는 실제 경험을 입력하는 대괄호 형식이다.

## 배송 방식별 페이백 계산 (2026-10-28)

- 최신 사용자 기준으로 빈박스는 상품 가격 + 리뷰비, 실배송은 리뷰비만 정산한다. 실배송 리뷰비 0원은 받을 금액 0원·정산 없음이다. 미정산 잔액은 각 상품 총 받을 금액에서 실제 입금액을 차감하되 0원 미만으로 내려가지 않는다. 구매 합계와 실제 입금 이력은 유지한다.

## 실제 주문내역 OCR 오류 수정 (2026-10-28)

- 오류 화면의 `/assets/src-DoZp4Pke.js` 요청이 삭제된 파일 대신 HTML을 200으로 받는 것을 확인했다. OCR 클라이언트를 기본 페이지 번들에 포함해 업로드 시 오래된 해시 파일을 요청하지 않도록 변경했다. HTML은 `no-store`, 없는 `/assets`·`/ocr` 파일은 404로 응답한다.

## 리뷰 처리일 기준 캘린더 (2026-10-28)

- 캘린더 월별 건수·날짜 셀·선택일 목록을 실제 리뷰 처리일(완료 입력창의 리뷰 작성일) 기준으로 변경했다. 완료 상태이면서 처리일이 있는 기록만 표시하며 마감 미정도 포함한다. 처리일이 없는 기존 완료 기록과 작성 전 기록은 날짜를 추정해 표시하지 않는다. 부제목·범례·빈 상태도 처리 내역에 맞췄다.
- 마감 알림과 대시보드의 마감 확인 버튼은 내 리뷰의 마감 임박 목록으로 연결한다. 사용 가이드도 처리일 기준으로 안내한다.
- 빌드와 브라우저 검사 3종(신규 캘린더, 대시보드 작성 전 목록, 기존 모바일 메뉴·필터·캘린더·등록)을 통과했다. 별도 DB에서 마감일과 다른 처리일, 마감 미정, 같은 날 3건, 지난달 처리, 처리일 없는 기록, 빈 날짜, 월 이동을 확인했다. 실제 날짜 수정·작성 전 복귀·리뷰 완료 후 즉시 갱신과 새로고침 후 저장 유지, 마감 알림 이동도 검증했다.
- 1440/390/360px에서 가로 넘침 없이 날짜 선택과 상세 모달이 동작하며 PC·모바일 캡처를 시각 검토했다. localhost:3001의 HTML·JS·CSS가 최신 빌드와 일치한다.

## 내 리뷰 칸반 보기 (2026-10-28)

- 내보내기 오른쪽에 칸반뷰로 보기/테이블뷰로 보기 버튼을 추가했다. 흰색 카드·회색 제목의 3열(작성 전, 리뷰 완료, 정산 완료)에 단계별 건수를 표시한다. 카드 본문은 상세 모달, 하단 흰색 버튼은 기존 리뷰/정산 입력을 연다. 완료 저장 후 카드 위치·건수·KPI를 갱신하며 취소하면 유지한다.
- 검색·플랫폼·리뷰 타입·상태 필터·정렬·CSV가 같은 조회 조건을 사용하고, 칸반은 페이지 제한 없이 전체 결과를 열 내부에서 스크롤한다. 표시할 열·페이지 이동은 테이블에서만 보인다. 테이블 복귀 시 필터와 열 설정을 유지하며, 보기 방식은 현재 계정의 브라우저에 저장한다.
- 별도 DB의 22개 기록으로 20건 초과 표시, 선입금된 작성 전, 부분 입금, 정산 없는 실배송, 날짜 미정·마감 임박, 긴 이름, 빈 열·검색 결과 없음을 검증했다. 실제 리뷰 완료·부분 입금·정산 완료와 새로고침 후 저장 유지, 필터된 CSV, 테이블 복귀도 확인했다.
- 빌드 및 브라우저 검사 5종(칸반, 리뷰 타입 필터, 등록부터 정산·삭제, 모바일 메뉴·등록, 표시할 열)을 통과했다. 1440/768/390/360px 화면에서 가로 넘침 없음, 내보내기 옆 전환 버튼, 모바일 가로 이동·상세 모달, 칸반 WCAG 2 A/AA 검사 위반 없음을 확인했다. PC·모바일 화면을 시각 검토했다.

## 내 리뷰 KPI 세분화·정산일 라벨 (2026-10-28)

- KPI 카드 4개를 등록 건수/정산 완료, 작성 전과 실배송·빈박스별 건수, 리뷰 완료, 받을 페이백과 상품 원가·리뷰비 잔액으로 구성했다. 타입 미지정 기록은 임의 분류하지 않고 별도 건수를 표시한다. 검색·플랫폼·리뷰 타입과 같은 조건으로 집계하고 상태 탭·페이지·테이블/칸반 전환에는 범위를 유지한다.
- 사용자 답변에 따라 부분 입금을 상품 원가부터 차감한다. 원가를 다 받은 뒤 남은 입금액을 리뷰비에 반영하며, 두 잔액의 합은 기존 받을 페이백과 일치한다. 실제 데이터와 입금 원장은 변경하지 않는다. 실배송은 리뷰비만 포함하고 0원 정산 없음은 정산 완료 수에 포함하지 않는다.
- ‘최근 입금일’을 표 제목·상세·수정창·CSV에서 제거하고 ‘정산일’로 통일했다. 날짜 저장 및 실제 입금 이력은 유지한다.
- 빌드, 단위/API 검사 12개, 브라우저 검사 6종을 통과했다. 별도 DB에서 부분/전체 입금 후 잔액·건수 갱신, 리뷰 완료 후 작성 전 타입별 건수 갱신, 검색·필터·0값·칸반·내보내기·새로고침을 확인했다. 단위 검사에서 미지정 타입·선입금·원가를 넘긴 부분 입금·기존 과입금 기록의 음수 방지·원본 보존을 검증했다.
- 1440/1024/768/601/390/360px에서 가로 넘침과 카드 내부 잘림이 없고 PC·모바일 화면을 시각 검토했다. KPI WCAG 2 A/AA 검사 위반 없음. 기존 등록·정산·삭제, 상세 필드, 모바일 메뉴, 필터, 칸반 검사도 통과했다.

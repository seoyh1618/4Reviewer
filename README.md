# For Reviewer

리뷰 상품부터 리뷰 일정, 페이백까지 관리하는 개인용 웹앱입니다. 계정별 데이터는 운영 서버의 PostgreSQL에 저장되며, 로컬 개발은 SQLite를 지원합니다. 브라우저 저장소만 사용하는 모형이 아닙니다.

## 실행

Node.js 24 이상이 필요합니다.

```sh
npm ci
npm run dev
```

개발 화면: http://localhost:5173 · API: http://localhost:3001

배포 빌드로 로컬 실행:

```sh
npm run build
npm start
```

접속 주소: http://localhost:3001

같은 Wi-Fi에 있는 휴대폰에서는 실행 중인 컴퓨터의 로컬 IP와 포트 3001을 사용하세요. 컴퓨터가 켜져 있어야 하고 방화벽이 해당 연결을 허용해야 합니다. 외부 인터넷에 배포된 주소는 아닙니다.

## 제공 기능

- 링크 공유 썸네일은 실제 로그인 첫 화면(회전 그래픽, 계정·비밀번호 입력란, 로그인 버튼)을 담은 `public/social/login-screen-v2.jpg`(1200×630)를 사용합니다. 홈페이지와 서비스 소개의 Open Graph/X 이미지 메타데이터에 동일하게 연결했습니다. `npm run build` 후 `node scripts/prepare-share-preview.mjs`로 실제 로그인 화면을 불러오는 촬영용 HTML을 생성할 수 있습니다. 별도 로컬 서버의 `/share-preview.html`에서 빈 입력란을 확인한 뒤 캡처하며, 촬영용 HTML은 다음 빌드에서 제거되어 배포되지 않습니다.
- 휴대폰 홈 화면에 설치하는 PWA 지원. 로그인 후 ‘내 계정 → 앱 설치’에서 기기별 설치 안내를 열 수 있습니다. Android Chrome은 설치 이벤트가 제공되면 직접 설치 버튼을 표시하고, iPhone Safari는 공유 → 홈 화면에 추가를 안내합니다. 설치한 아이콘은 독립된 앱 화면으로 열립니다.
- PWA는 운영 HTTPS 주소에서 사용합니다. 리뷰·정산 조회와 저장에는 인터넷 연결이 필요하며 오프라인 새 실행은 연결 안내 화면을 표시합니다. 서비스워커는 공개 `/offline.html`만 캐시하며 로그인 화면, 개인 데이터, API 응답, 주문내역 이미지는 캐시하지 않습니다. 앱 코드는 탐색할 때마다 네트워크에서 불러옵니다. 오프라인 안내를 바꿀 때는 `public/sw.js`의 캐시 버전도 갱신합니다.

- 기본 서체는 Pretendard Variable 1.3.9. 폰트를 사이트에서 직접 제공하며, 화면에 필요한 글자 묶음만 로드. 라이선스는 `/licenses/pretendard-OFL.txt`에 포함
- 이름 입력 없이 이메일 또는 아이디 중 하나로 회원가입·로그인·로그아웃, 로그인 상태 유지, 개인별 데이터 분리
- 상품 등록·수정·삭제, SKU·주문번호·구매 계정명·판매처·플랫폼·리뷰 타입·구매일·금액 관리
- 사진·텍스트·별점·동영상·구매만 유형, 리뷰 마감일·실제 작성일과 완료 상태
- 신규 등록은 구매금액 옆에서 리뷰비를 입력하며, 별도 예상 페이백 영역은 표시하지 않음. 상품값 페이백은 리뷰 타입에 따라 자동 계산하고 작성 전·입금액 0원으로 시작. 리뷰 완료·정산 단계에서 실제 작성일·입금액·입금일·입금자명 기록
- 내 리뷰·페이백 표는 화면의 가용 너비를 사용하고, 셀 여백 6px × 10px·약 47px 행 높이로 밀도를 높였습니다. 한 페이지에 최대 20개를 표시합니다.
- 내 리뷰 표 위에는 등록 건수/정산 완료, 작성 전(실배송·빈박스별 건수), 리뷰 완료, 받을 페이백(상품 원가·리뷰비별 잔액)을 흰색 KPI 카드 4개로 표시합니다. PC는 한 줄로 표시하고 모바일 화면(820px 이하)에서는 숨깁니다. 검색·플랫폼·리뷰 타입에 따라 집계하고 상태 탭·페이지 이동에는 전체 진행 현황을 유지합니다. 부분 입금은 상품 원가부터 차감하며 실제 입금 이력은 그대로 보존합니다.
- 내 리뷰의 내보내기 옆에서 테이블·칸반 보기 전환. 칸반은 작성 전·리뷰 완료·정산 완료의 3열과 단계별 건수를 표시하며, 검색·필터·정렬·내보내기를 유지. 카드에서 상세 모달과 리뷰/정산 입력을 열고 저장하면 해당 열과 KPI를 갱신. 모바일은 가로 스크롤, 각 열은 세로 스크롤이며 전체 조회 결과를 표시. 보기 방식은 계정별로 현재 브라우저에 저장
- 상품·페이백 목록의 맨 오른쪽에 고정한 ‘진행 단계’ 컬럼에 화살표 없는 다음 단계 버튼 하나만 표시: 작성 전에는 리뷰 완료, 리뷰 완료·부분 입금에는 정산 완료 전환. 입력창에서 저장하면 버튼과 통계가 갱신되며 전액 정산 후에는 완료 표시로 전환. 받은 금액이 없는 0원 상품도 정산창에서 리뷰비 추가 가능
- 상품 상세는 흰색·회색 중심의 2열 정보 배치. 변경 이력과 페이백 수령현황은 표시하지 않으며, 본문만 스크롤하고 하단 왼쪽 닫기·오른쪽 수정·맨 오른쪽 정산 완료 버튼을 유지. 작성 전에는 마지막 버튼을 리뷰 완료로 표시
- 상품 등록·리뷰 완료·정산 단계에서 상품값 페이백 외에 추가로 받는 리뷰비 입력. 총 받을 금액·미정산 잔액·대시보드·통계·CSV 반영
- 계정주·연락처·카톡 이름을 분리 관리, 18개 전체 열/핵심 열 전환, 상품명 고정과 표 내부 가로 스크롤
- 리뷰 마감일은 미정이면 빈 값으로 등록 가능. 카톡 이름은 실제 리뷰 제안(오퍼)을 보낸 상대방의 이름을 입력하도록 안내
- 대시보드, 상품 검색·필터·정렬·페이지 이동, 캘린더, 월별/플랫폼별 통계
- 리뷰 캘린더는 리뷰 완료 시 입력한 실제 리뷰 처리일(리뷰 작성일)을 기준으로 월별 건수와 날짜별 완료 목록을 표시. 처리일 수정·작성 전 복귀 시 즉시 갱신하며, 처리일 없는 기록은 날짜를 추정하지 않음. 마감 알림은 내 리뷰의 마감 임박 목록으로 연결
- 대시보드의 다가오는 리뷰는 작성 전 리뷰 전체를 표시. 마감일이 이른 순으로 정렬하고 같은 마감일 또는 마감 미정 항목은 오래 등록한 순으로 배치하며, 마감 미정은 날짜가 있는 리뷰 다음에 표시. 많은 항목은 카드 안에서 스크롤하며 전체 보기에서 작성 전 목록으로 이동
- 나의 리뷰 통계에서 연도·월 선택, 통계 카드·차트·플랫폼별 활동·상세 표 동시 필터. 구매는 구매일, 입금은 실제 입금일 기준으로 집계하며 선택 기간은 새로고침·뒤로 가기에도 유지. 전체 데이터 내보내기는 모든 기록을 제공
- 대시보드·통계의 월별 막대에 마우스를 올리거나 모바일에서 누르면 연월·구매금액·실제 입금액 표시. 다시 누르기·바깥 누르기·Esc로 닫기, 키보드 초점으로 금액 확인 지원
- CSV 내보내기 (UTF-8 BOM, 스프레드시트 수식 삽입 방지)
- 한국어 주문 이미지 OCR, 자동 폼 입력·원문 확인·수정
- 구매 플랫폼: 쿠팡·네이버·11번가·기타 직접 입력, 리뷰 타입: 실배송·빈박스
- 모바일 목록은 상품명·플랫폼·리뷰/정산 상태·마감/유형·금액만 표시하는 짧은 카드로 제공. 카드 선택 시 목록 위에 상세 모달을 열고 전체 정보·진행 단계 제공
- 모든 리뷰/페이백 상태 탭에 건수 표시. 검색·플랫폼·리뷰 타입 필터와 리뷰·정산 저장 결과를 즉시 반영
- 모바일 하단 내비게이션·전체 화면 입력 폼

## OCR의 범위

이미지는 외부 OCR 서비스나 앱 서버에 전송하지 않습니다. Tesseract.js Web Worker와 한국어 모델(영문 문자 포함)을 같은 서버에서 로드하고 기기 안에서 인식합니다. 작은 글자가 있는 캡처는 확대해 인식하며, OCR 실행 파일과 모델은 업로드할 때만 준비합니다. `predev`와 `prebuild`에서 필요한 모델/worker 파일을 준비합니다. 모델 라이선스는 해당 npm 패키지에 포함되어 있습니다.

한 이미지의 단일 주문 입력을 돕는 기능입니다. 인식이 끝나면 상품명·구매 플랫폼·구매일·구매금액·주문번호·판매처 중 확인된 값을 폼에 자동으로 채웁니다. 쿠팡처럼 상품명 라벨 없이 상품 카드가 표시되는 주문상세도 지원하며, 할인 전 상품가격보다 최종 결제금액을 우선합니다. 주문번호가 있으면 추가 관리 정보가 펼쳐집니다. 리뷰비와 리뷰 타입은 기존 입력을 유지하고 수령인의 이름·전화번호를 구매 계정이나 리뷰 담당자 정보로 옮기지 않습니다. 여러 상품이 보이는 주문은 상품명과 전체 결제금액을 임의로 한 상품에 배정하지 않습니다. 원문과 채워진 값을 수정한 뒤 저장할 수 있습니다. 제공된 실제 쿠팡 캡처 한 건은 PC·모바일 크기의 Chrome에서 검증했으며, 모든 쇼핑몰·레이아웃의 정확도를 보장하지는 않습니다.

## 데이터와 운영

- 기본 데이터 파일: `data/reviewer.sqlite`. `data/`와 `.env`는 버전 관리 제외.
- `.env.example`을 `.env`로 복사해 경로·포트를 설정할 수 있습니다.
- 회원가입은 아이디 또는 이메일 중 하나와 8~128자 비밀번호, 운영 서버에 설정된 회원가입 코드를 사용합니다. 코드 변경은 For Reviewer 전용 `.env`의 `SIGNUP_CODE`를 수정한 뒤 앱에 반영합니다.
- 비밀번호: 무작위 salt + scrypt. 세션: 토큰 해시만 DB 저장, HttpOnly/SameSite=Lax 쿠키.
- 로그인 아이디는 영문·숫자·밑줄 4~30자로 대소문자를 구분하지 않으며 중복을 허용하지 않습니다. 기존 회원은 이메일로 로그인한 뒤 계정 설정에서 현재 비밀번호를 확인하고 아이디를 등록·변경할 수 있습니다. 기존 이메일 로그인과 기록은 유지됩니다.
- SQLite는 시작 시 기존 계정과 연결 기록을 보존하면서 아이디 전용 가입을 지원하는 구조로 갱신합니다. PostgreSQL은 배포 전 스키마 소유자 권한으로 `node --env-file-if-exists=.env server/migrate.mjs`를 실행해 버전 3으로 갱신해야 합니다. 런타임 계정은 스키마 변경 권한이 필요하지 않습니다.
- 모든 상품·입금 API에서 로그인 사용자 소유권 검사. 수정·삭제에는 버전 검사를 적용합니다.
- 계정은 빈 목록으로 시작합니다. 예시 체험 기능은 제공하지 않습니다.
- 구매금액 합계와 월별 집계는 상품 구매금액만 계산합니다. 추가비용은 입력·표시·내보내기에서 제외했습니다.
- 추가 리뷰비는 지출과 별개인 추가 수령 예정액입니다. 총 받을 금액은 예상 페이백과 추가 리뷰비의 합계이며, 실제 입금액과 입금월별 통계는 정산 입력 시 반영됩니다. 기존 추가비용을 리뷰비로 전환하지 않습니다.
- 리뷰 타입에 따라 정산액을 계산합니다. **빈박스는 상품 가격 + 리뷰비**, **실배송은 리뷰비만** 포함하며 실배송의 리뷰비가 0원이면 받을 금액도 0원입니다. 받을 페이백은 상품별 정산액에서 실제 입금액을 뺀 잔액(최소 0원)의 합계입니다. 구매금액·리뷰 타입 변경과 OCR 적용 시 같은 규칙으로 갱신합니다. 리뷰 타입이 없는 구형 기록은 선택 전까지 기존 페이백을 유지하며, 실제 입금 기록은 변경하지 않습니다.
- 기존 플랫폼은 기타 직접 입력 값으로 보존합니다. 이전 기록의 리뷰 타입은 미입력으로 표시하며 수정 시 선택합니다.
- 부분 입금은 실제 입금일별 원장에 저장합니다. 누적 입금액 감소/날짜 정정은 현재 잔액을 정정한 날짜로 다시 집계합니다.
- 운영은 전용 PostgreSQL·영구 볼륨을 사용합니다. 앱 재배포와 DB 데이터는 분리되며 동시 수정은 원자적 버전 검사로 보호합니다. 자세한 접속·배포·백업 절차는 [운영 안내](docs/DEPLOYMENT.md)를 참고하세요.
- Node 24의 내장 SQLite API는 런타임에서 experimental 경고를 표시합니다. 지원 버전 고정 및 운영 검증이 필요합니다.

실서비스 배포 시 HTTPS, `COOKIE_SECURE=true`, 정확한 `APP_ORIGIN`, 필요 시 `TRUST_PROXY=1`, 영구 저장소와 암호화 백업/복구 절차를 구성하세요. 서버리스 임시 파일시스템에는 그대로 배포하면 안 됩니다.

이메일 인증·비밀번호 재설정·소셜 로그인·탈퇴·알림 발송·쇼핑몰/은행 자동 연동·스프레드시트 일괄 가져오기는 현재 구현 범위에 포함되지 않습니다. 일반 사용자 공개 전 공인 HTTPS 인증서·도메인과 실제 휴대폰 기기 검증이 필요합니다.

```sh
npm test

npm run test:e2e
```

브라우저 테스트는 Google Chrome 채널을 사용합니다. Chrome이 설치되어 있어야 합니다. 테스트 DB는 `test-results/`에 생성하고 실행 중인 앱의 `data/`를 사용하지 않습니다.

## 구조

```text
src/               화면·컴포넌트·브라우저 OCR
shared/domain.mjs  검증·금액 집계·OCR 텍스트 추출
server/            인증·개인 데이터 API·SQLite
scripts/           로컬 OCR 모델 준비
tests/             API·도메인·브라우저 테스트
docs/              기획·검증·화면 캡처
```

사용자별 상품·리뷰·입금 이력은 PostgreSQL에 저장됩니다. DBeaver 조회용 컬럼, 이력 보존 기준과 집계는 [리뷰 데이터 가이드](docs/REVIEW-DATA.md), 바로 실행할 쿼리는 [SQL 모음](docs/REVIEW-DATA.sql)을 참고하세요.
